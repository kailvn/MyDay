# MyDay 交互定稿（INTERACTION v1）

> 状态：定稿，已实施。对《SCHEMA-REDESIGN》§5.8 的类型识别做了「激活即推断」细化，
> 对 §2.6 模板 defaults 扩展了时间占位 token；表结构未变。
> 本文自包含；修订历史见文末。

## 0. 设计原则（沿承需求文档）

1. **快**：速记路径（打字 → 回车）永远最短；其余信息渐进披露。
2. **确定性**：类型、时间、字段值全部可解释，宁可报错不猜测、不静默改写。
3. **一个面板**：创建 / 编辑 / 模板三态共用 `ItemPanel` 一个组件，优化只改一处。
4. **模板存意图，条目存事实**：模板的时间默认是占位符（应用时解析），
   条目上的时间永远是具体时刻。

## 1. 统一面板（ItemPanel 三态）

| 态 | 入口 | 类型 | 专属内容 |
|---|---|---|---|
| 创建 | 快捷键 / 托盘 / CLI、日历双击、记录页模板按钮 | 自动识别，保存前可改口一次 | 模板 chips、粘贴截图、文件链接 |
| 编辑 | 各视图「编辑」按钮 | 锁定徽标（类型创建即定） | 删除按钮、创建/修改时间、已完成勾选 |
| 模板 | 「模板」页 → 模板管理（新建 / 编辑） | `tplItemType` 可选 | 模板名 / 图标 / 标签 / 说明 / pinned、时间占位池 |

窗口形态：快速添加为独立置顶小窗（windowMode），主窗口内为弹层，组件相同。

各视图点击条目行打开**只读详情面板**：非空信息与图片（自管理附件）纵向排版，
图片双击放大预览；待办在此一键「标记完成 / 改为未完成」，编辑从面板内「编辑」进入。
待办只有两态：未完成（todo）/ 已完成（done）——列表勾选、编辑态「已完成」勾选、
详情按钮三处等价。

## 2. 激活模型（创建态核心）

- 字段两态：**chip（未激活，全部字段可见）** / **展开控件（激活）**。
- **激活即推断**：点开类型独特字段的那一刻类型就定并回显，不需要等填值。
  - 点「时间」（开始+结束成组激活，见下）→ 日程
  - 点「截止」→ 待办
  - 点「发生时间」或 scope=log 的自定义字段 → 记录
  - 什么都不激活 → 待办（裸文本默认）
- **时间组 chip**：开始/结束只属于日程且必须成对存在，归并为一颗「＋ 时间」
  chip——激活同时展开两行、取消同时撤掉；行内再各自填值。
- **冲突隐藏**（与 DB CHECK 对齐）：类型确认后只留该类型的字段。

| 识别为 | 展示的时间字段 | 隐藏 |
|---|---|---|
| event | 时间组（开始、结束，成对） | 截止、发生时间 |
| task | 截止（唯一；点截止即确认待办，时间组一并隐藏） | 时间组、发生时间 |
| log | 发生时间（必填） | 时间组、截止 |

  两个例外：**类型未确认**（裸面板，无任何激活/显式类型/模板）时全部字段 chip
  可见——否则没有入口能点到其他类型的字段；**编辑态**有值的字段始终可见
  （隐性清除 = 丢数据，可显式 × 清除）。

- **回退**：chip 上的 × = 取消激活（值一并清空），类型回到自动、隐藏字段回来；
  类型下拉「改口」是万能逃生门（保存前一次）。编辑态 event 的开始/结束不可撤。
- **改口与已激活值冲突 → 保存报错**（如改口日程但已填截止），提示先移除，不静默清除。
- 前置折叠：创建态默认只露「标题 + 模板」，「＋ 时间 / 字段 / 标签」展开全部字段
  （chip 形态）；有预设内容时自动展开。

## 3. 激活瞬间的默认值注入

优先级从高到低，取第一个命中：

1. **模板 token**：已应用模板的时间列占位，按锚点日解析；
2. **日历锚点日**（双击格子带入）：开始=当天 09:00、结束=当天 18:00、
   截止=当天 23:59、发生时间=当天 12:00（仅过去日，否则回落「现在」——记录不能发生在未来）；
3. **类型回退**：event 开始=下一整点、log 发生时间=现在，其余留空。

## 3.1 时间快捷标签（行内一键填充）

标签是「人话 → token」的映射，点击立即解析成具体时间填入；**同一标签按所在行
映射到不同基准**——这正是 @ 文法双族语义的 UI 化，文法本身零扩展：

| 行 | 标签（token） | 基准 |
|---|---|---|
| 开始 | 下一整点（`@next_hour`）、一小时后（`@now+1h`）、明天 9:00（`@d+1T09:00`） | 当前时刻 / 锚点日 |
| 结束 | 半小时后（`@start+30m`）、一小时后（`@start+1h`）、两小时后（`@start+2h`） | 已填的开始时间 |
| 时段（同时填首尾） | 全天（`@d0`–`@d0Tend`）、工作时间（`@d0T09:00`–`@d0T18:00`）、午休（`@d0T12:00`–`@d0T14:00`） | 锚点日 |

- 「全天」是时段标签而非开关：选中后开始/结束变日期输入，存 `all_day` +
  当天 00:00–23:59；点其他时刻标签即退出全天。
- 时段标签行仅日程（时间组）提供；待办保留「明天」、记录保留「现在」单标签。

## 4. 日历

- **单击格子 = 选中**，右侧当天面板显示；**双击格子 = 创建**（锚点日=当天，类型自动）；
  侧栏「＋ 新建」等价于双击（单击路径保留，双击是加速键）。
- 当天面板按「所有内置时间字段中与当天关联的条目」分三节（时间升序）：
  - **日程**：event 与当天相交（跨天日程两头都算）+ 当天开始的待办；
  - **到期**：due_at 落在当天；
  - **记录**：occurred_at 落在当天。
- 数据层：一次 `list_items_window(from, to)`（OR 语义：start/end 区间相交 ∨ due ∨ occurred；
  NULL 列自然不命中）取整月，网格圆点与当天面板共用。
  修复了旧版「记录按 created_at 归日、due-only 待办不显示」两个 bug。
- 切月时选中日收进新月（今天或 1 号）。

## 5. 模板系统

- **模板 = 预填充的面板**。模板页「新建 / 编辑模板」打开的就是统一面板的模板模式：
  像填条目一样填一遍默认值，「存为模板」。
- defaults 收集范围：默认标题、默认备注、标签、时间占位（见下）、
  字段值（字段 id 键，应用时物化 field_defs）。待办状态不入模板（新建恒为未完成）。
- **fields = 随模板启用的字段**（含未设默认值的占位字段）：应用时一律激活，
  有默认值的带值、无默认值的留空现场填；保存模板时以完整字段定义随 defaults 一并物化。
- **时间占位池**：时间列不存绝对时间，存 `@token`（文法与解析器在
  `core/src/tpltime.rs`，前端镜像 `lib/tpltime.ts` + golden 用例锁定一致）：

  ```
  @<base>[<offset>][T<time>]
  base   = now | next_hour | start | d0 | d+N | d-N
  offset = (+|-)数字(m|h)          # 仅 now / start 基准
  time   = HH:MM | end(=23:59)     # 仅 d 基准
  ```

  两族语义：**clock 族**（now/next_hour）相对当前时刻；**day 族**（d*）相对
  **锚点日**（日历选中日，缺省今天）的本地时区。`@start+30m` 仅 end_at 可用
  （= 开始后半小时）；`occurred_at` 仅接受 `@now` / `@now-…`（记录不能在未来）。
- 官方池（UI 人工标签，文法是超集）：现在、30分钟前、1小时前、下一小时、
  当天 09:00 / 18:00 / 结束、明天 09:00 / 结束、开始后30分钟。
- **解析权威在 core**（`add_item` 合并 defaults 时解析，`anchor_day` 参数可指定锚点日，
  缺省今天）——记录页一键记录、CLI `--template` 路径无需前端参与；
  面板用 TS 镜像在激活瞬间解析出可编辑的具体时间。模板保存时校验 token。
- 应用模板 = 类型即定（§5.8 规则 1）+ 激活其默认值字段与启用字段 + 注入解析后的时间；
  取消应用按「值仍是模板默认」反向回收。
- 快速添加裸面板（类型未定）直接列出全部模板（chip 上标注类型），点哪个类型即定哪个；
  类型已定后只列同型模板。
- 记录页按钮：pinned 的 log 模板。带字段值默认的可一键记录（core 合并），
  无字段默认的打开面板补值（自动应用该模板）。

## 6. 提醒（1:N）：存意图，不做一次性时刻

提醒与模板时间同哲学：**存相对意图（spec），发生时刻由提醒环运行时展开**。
改动条目的开始/截止后，提醒自动跟随，无需逐条改时间。

### 6.1 spec 文法（与模板占位同一套语言，见 `core/src/tpltime.rs`）

| spec | 含义 | 适用 |
|---|---|---|
| `@start` / `@start-10m` / `@start-1h` / `@start-1d` | 开始时 / 提前 10 分钟 / 1 小时 / 1 天 | event |
| `@due` / `@due-1h` / `@due-1d` | 截止时 / 前 1 小时 / 前 1 天（用户显式选择） | task |
| `@dailyT09:00` | 期间每天 09:00（期间 = event [start,end]、task [start 或创建, due]） | event / task |
| RFC3339（不带 @） | 绝对一次性时刻（"自定义时刻"落这里） | 全部 |

收窄规则：`@now` 族不作为提醒 spec（存储后会随评估漂移，永不触发）——
"30 分钟后提醒"由 UI 落成绝对时刻；log 无期间，不适用相对锚点，通常也不提醒。

### 6.2 运行机制

- `reminders.spec` 为唯一事实源；提醒环每 30 秒展开 occurrence，
  `reminder_log(reminder_id, 解析时刻)` 复合键去重——同一 spec 因条目时间变动
  产生新时刻自然重新触发，历史时刻不重发。
- **snooze 不改 spec**（会毁掉相对规则），而是插入一条绝对 spec 的覆盖行
  「到 until 再响一次」。
- 自动默认提醒（设置「默认提前 N 分钟」）同样只锚「开始」且仅当开始在未来时
  生成 `@start-Nm`；无开始的待办与记录不自动补。
- 面板提醒行：token 显示为池标签 chip（如「截止前 1 天」），绝对时刻显示
  datetime 输入；「＋ 提醒」按类型给池 + 自定义。保存整体替换，
  spec 语法在 core 校验（`@token` 或 RFC3339，其余拒绝）。

### 6.3 全天（时段标签，非开关）

- 「全天」只属于日程语义：它是时间组下的一个**时段标签**（见 §3.1），
  选中即填当天 00:00 / 23:59 并置 `all_day`（开始/结束变日期选择，
  存储约定 = 当天 00:00 / 23:59 本地 → UTC），展示只到日期；
  点其他时刻标签即退出全天。日历窗口查询天然兼容。
- 待办截止与记录没有全天语义（`due_all_day` 列保留但 UI 不再暴露）。
